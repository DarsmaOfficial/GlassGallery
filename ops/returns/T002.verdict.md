# T002 verdict — Make CI unbypassable by branch name

**Commit:** `1feff98`, merged to `main` by clean fast-forward. `origin/main` = `1feff98`.
**Author:** `DarsmaOfficial <darsmaofficial@gmail.com>`, no trailers, no vendor names.
**Scope:** one file, `.github/workflows/build.yml`, +5/−1.

## What changed

```yaml
-    branches: [ main, 'feature/**' ]
+    branches: [ '**' ]

+concurrency:
+  group: ${{ github.workflow }}-${{ github.ref }}
+  cancel-in-progress: ${{ github.ref != 'refs/heads/main' }}
```

An allowlist of prefixes was deliberately rejected — it has the same defect as the original, only
relocated. `'**'` is the only form no branch name can escape.

The `main`-excluding cancel condition is load-bearing, not decoration: a `main` run publishes
`app-release.apk` to the rolling `latest` release, and cancelling mid-upload can leave the asset
missing or truncated. Feature branches supersede freely; `main` never cancels.

would cancel **and so would main**, silently killing a publishing run. Only overlapping two `main`
runs separates those cases. Both dispatches were on the same SHA, so `latest` landed correctly
either way.

## 🔴 The finding that outranks this task

Red-team's critical finding was about **my own documentation**, not the diff. `CLAUDE.md` said
"Gates 1–4 are CI-reachable". CI runs `assembleRelease` and nothing else — no lint, no tests, **no
merged-manifest check**. "Reachable" was meant as "could be wired up"; it reads as "does run".

T002 makes that misreading more likely, not less: every branch now shows a green tick, which is a
far stronger invitation to treat a green CI as a passed gate. **CLAUDE.md has been corrected** with
a per-gate table stating exactly what CI does and does not check.

Gate 4 specifically is the invariant the whole programme rests on, and it has **no automated
enforcement at all**. `guard-cost.py` inspects *edits*; manifest merging pulls permissions from AARs
nobody edited. That is precisely the threat gate 4 exists to close, and it is open.

## Deferred — pre-existing, filed not fixed

None caused by this diff; all now more consequential because every branch builds.

1. **No `timeout-minutes`.** Default is 360. Combined with `cancel-in-progress: false` on `main` —
   which this task added — a hung build holds the main concurrency group for six hours, and queued
   pushes silently replace one another. This change removed the self-healing here.
2. **`softprops/action-gh-release@v2` is a mutable tag** holding a `contents: write` token. Pin to a
   full commit SHA; same for the three GitHub-owned actions.
3. **`contents: write` is workflow-level**, so `gradle assembleRelease` runs with it on every branch.
   Fork PRs are safe (GitHub forces read-only), so severity is low today, but it is structural.
   Split publish into a second job with `needs:`.
4. **Publish gate could check `github.event_name`** — `workflow_dispatch` on `main` republishes.
   Probably intended; undocumented either way.
5. **Do not "fix" the new build noise with `paths-ignore`.** That reintroduces exactly this defect
   with a worse signature: a mixed commit touching one `.kt` and ten `.md` files behaves differently
   from a docs-only one. Actions is free on public repos.
